# Ascend KV 缓存容量及摘要服务预算

2026-11-04，Ascend 910B4-1（物理4、逻辑0），Torch/torch-npu 2.9.1、vLLM 0.18.0、CANN 9.1.1。正式服务的显存参考上限为实验前整卡采样 **50307 MiB（49.128 GiB）**。

用户要求禁止 eager 后，所有验收数据均重新使用 `enforce_eager=False`、`FULL_DECODE_ONLY` 测量；开启 MTP2 时，草稿模型也必须捕获图。早期目录 `kv-quant-20261104` 的 eager 数据仅作排障记录，排除在本页验收结果之外。图模式原始数据、命令、源码快照和逐请求输出位于 `/home/qwen-models/reports/qwen3.8-27b/kv-quant-graph-20261104`。

## 摘要引擎实际需要的上下文

实际运行的 `meetnote-e2e-summary.service` 工作目录为 `/root/repositories/meetnote`，端口8010，调用8100上的 `qwen3.8-27b-optimized-v1`。

真实进程环境及配置类核对结果：输入24576、输出7168、协议/模板预留1024，总预算32768，模型调用并发2。输入预算包含任务指令、输入JSON及结构化输出schema的本地token计数；协议预留覆盖服务聊天模板等额外开销。全文超过预算会分窗并逐层汇总。

正式大模型服务默认每路57344输入、8192输出，四路64K。64K是专项适配中固定的已验收软件配置，不是硬件上限。

## 显存差异

正式服务实验前：Torch实际分配42.471 GiB，其中KV/GDN缓存池22.473 GiB，其余权重和执行资源19.998 GiB。整卡HBM采样49.128 GiB。allocated、reserved、整卡HBM是不同口径，不可相加；缓存池预分配也不代表摘要请求正在使用全部容量。

NVIDIA的[40GiB服务记录](nvidia-gpu3-40g-service.md)同样为四路，完成了每路128K输入＋32K输出的160K测试。差异包括：

- Ascend原服务全注意力KV为BF16，NVIDIA为FP8；相同token数的KV有效载荷相差约一倍。
- Ascend原服务启用MTP2，包含额外注意力层和状态开销；NVIDIA该配置关闭MTP。
- NVIDIA词嵌入和输出头均为INT4；Ascend原服务为BF16词嵌入、INT8输出头，主干量化配方与格式也不同。
- Ascend混合注意力/GDN缓存采用统一页布局，存在填充和取整开销。两端都保留FP32 GDN递归状态，不能把平台差距全归因于FP32。

四路64K、17层全注意力的BF16 KV有效载荷约17GiB；22.473GiB缓存池还覆盖GDN状态、页填充、取整及预留。

## 可用的KV量化方案

本机FP8 E4M3转换在 `aclnnInplaceCopy` 失败，错误码561103，因此没有把NVIDIA的FP8参数直接用于本机。采用当前安装栈提供的静态逐通道INT8 KV（C8），保留BF16残差、BF16 GDN卷积状态及FP32递归状态。

尺度来自对应权重、对应MTP配置的真实K/V校准，每通道 `max_abs × 1.2 / 127`，关闭MTP覆盖16层，开启MTP覆盖17层。有限材料校准及短问答/检索不等于完整质量评估。

仅改变KV dtype时，注意力页仍填充到原GDN页宽，容量没有增加。实验进程让原布局规则按INT8字节宽度计算：块从1536变为3072 token，每层页仍为6352896字节，实际INT8缓存才获得容量收益。未修改安装包文件。

C8解码补充了图捕获与回放参数更新：每次更新实际序列长度和块表，保留捕获/更新计数及最长回放长度，防止图冻结在预热长度。MTP的多查询通过因果前缀展开执行，每个查询只读取它能看到的KV。独立MTP图算子对齐相对L2为0.01148。

## 复现及服务恢复

实验由 `tests.performance.qwen38.ascendc_v2_experiment` 控制器独占设备，保存每项argv和源码快照，退出时恢复8100正式服务并执行真实请求。

入口为 `poetry run python -m tests.performance.qwen38.kv_capacity`。BF16校准使用 `--mode bf16`；C8使用 `--mode int8 --align-c8-pages --scales 对应校准文件`；候选权重再加 `--model 模型目录 --vocab4`。MTP使用 `--mtp 2`，容量使用 `--long`，短测速使用 `--speed`；每次必须指定全新的 `--output` 目录。

机器汇总通过 `summarize_kv_capacity 原始目录 --graph` 重建，明确区分池计算、实际长请求、主/草稿图验收和正式服务恢复结果。
