# Qwen3.8-27B / Ascend910B4 专项优化及完整验收

本报告使用独立实例的真实HTTP/SSE、NPU trace和逐题结果，原始目录为 `/home/qwen-models/reports/qwen3.8-27b/optimization-20261022`。比较基线是项目原有混合量化模型，未测完整BF16模型吞吐，因此所有加速比均相对原混合量化版本。

## 已采用的改动与结果

采用FFN尺度加载时缓存、目标/MTP输出头共享、GDN最后可复用提示检查点保留，以及49个指定投影的W8量化。完整验收、独立复测和普通生产CLI验收均通过。512-token生成单路吞吐55.15 → 60.65 TPS（+9.97%），四路 153.64 → 166.88 TPS（+8.62%）。

57K四路热重放吞吐 5.05 → 64.00 TPS（12.67倍），TTFT 54.208 → 4.691秒。该收益来自实际前缀命中恢复；候选五轮20个请求均命中55296 token。它不代表未见过的长文输入也能获得同等加速。

就绪态Torch实际分配 47.6747 → 42.4710 GiB，减少 5.2038 GiB；两者KV实分配相同，为 22.4732 GiB。

缩小预填充分块没有通过延迟与吞吐的平衡门槛，保持8192预算；不将未采用的约57%短流卡顿改善算入发布收益。

## 热点与对应适配

原始分段及内核证据见[热点报告](qwen38-hotspots.md)。单路decode中FFN约占累计设备工作量32%、输出头15.73%（目标5.32%、草稿10.41%）、GDN输出投影9.19%；长文prefill FFN约48%，其内部权重反量化相关工作约88%。这些是累计内核工作量，不能相加后解释为端到端墙钟比例。

### FFN尺度缓存

上游每层forward执行`weight_scale_second.to(x.dtype)`，64层融合gate/up及down共128次转换。适配保留上游FP32尺度合并顺序，在加载后将最终尺度一次舍入至BF16；权重、group、NZ布局和算子不变。真实0/30/63层、两类投影与M=1/3/6/12/38/117/1536/2048/6144/7680共60组，输出逐位一致、最大误差0。最终trace确认这两类尺度Cast由每个target forward 128次降为0，FFN matmul数量仍全部覆盖；其他Cast保留。单独就绪态减少0.2490 GiB。数值逐位对齐指这些算子，不表示整个生成序列必须逐字一致。

### 输出头共享和量化加载

目标模型与MTP原先分别驻留248320×5120的输出头。加载阶段核对全部参数名、shape、dtype、内容与量化方法后共享同一模块；推理过程中没有逐步比较或同步，仍然执行两侧各自需要的logits投影。相同隐藏态的两侧logits逐位一致。共享BF16头单独节省2.3682 GiB；采用W8头后共享的对象已经缩小，不能再把这2.3682 GiB与量化节省直接相加。

本机上游Qwen目标与MTP构造`ParallelLMHead`时未传quant_config，直接加载W8头会缺少weight_offset。适配只对248320×5120、量化描述明确为W8的输出头绑定官方W8执行方法。安装的vLLM/Ascend源文件没有因本实验被修改。

### GDN检查点保留

原LRU会在预填充压力下逐出四路提示最后可复用的GDN状态，导致全注意力块尚在、混合前缀却不能命中。只优先使用未缓存空闲块仍然无效：预热中这类空闲块曾耗尽，结束时又有空闲块不能反证未发生驱逐。

采用策略维持原块对象、hash查找、引用计数和空闲双向队列，另维护O(1)索引：先取未缓存空闲块，再回收较早GDN状态，最后按原LRU分配。保护范围仅为每提示/每GDN组最后一个可供MTP裁剪后复用的检查点；提示尾部不能重放的较晚状态不受保护。保护是软偏好，所有块都受保护时仍能回收，不固定占用或禁止驱逐。

专项调度器只在请求到来前接入Engine Core，要求1536对齐、17层全注意力缓存（含MTP）、三组各16层GDN、MTP2和FP32递归状态布局。测试覆盖重复hash、引用、reset、全保护退让、随机2000步分配，以及实际多路前缀增长/稳定性不变量。

### 仅量化指定的49个投影

从原始BF16重新量化48个GDN out_proj及1个lm_head，采用每输出通道对称INT8权重与官方逐token动态INT8激活。其他原混合量化张量保持原内容。三种独立配方均筛选，最后选择GDN+Head组合。实际尺寸35组投影验证均在预设容差内，最大relative-L2为 0.015850。这是有损量化，最终采用依据是完整生成质量评估；微基准中的eager事件跨度含主机提交间隙，不作为端到端加速比。

## 显存口径和此前四路失败

“项目显存”指进程或实例的总体占用，包含权重、KV/GDN状态、MTP、执行图、临时张量、工作区、分配器保留及运行时开销。它不是在“权重+KV”之外再加一遍的独立类别。Torch allocated、Torch reserved、NPU进程占用、整卡HBM是不同口径，不能直接相加。卡上无拥有进程时仍有约3417 MiB基础占用；磁盘模型大小也不等于设备驻留量。
